# DressTrack — запускаемая основа к EK1

Минимальный веб-API DressTrack: вход, проверка прав и чтение посылок в пределах доступа
пользователя. Паспорт и концепция безопасности — в [`PROJECT.md`](../PROJECT.md).

## Что уже реализовано

| Точка входа | Доступ | Что делает |
| --- | --- | --- |
| `GET /health` | Без входа | Проверка работы сервера и подключения к базе |
| `POST /auth/login` | Без входа | Выдаёт JWT на 1 час; одинаковый ответ на неверный логин и неверный пароль |
| `GET /parcels` | Все роли | Посылки только по привязке пользователя (D-01) |
| `GET /parcels/{id}` | Все роли | Карточка посылки; чужая и несуществующая — одинаковый 404; оператор не видит стоимость (D-02) |
| `GET /parcels/{id}/history` | Все роли | История статусов в тех же границах доступа |

Изменяющие операции (создание посылки, переходы статусов, выдача по коду, возврат) и
фоновая задача пока не реализованы — это D-03 и D-04 из
[проектных решений](../S04/DESIGN_DECISIONS.md).

## Окружение

- .NET SDK 10.0.x (проверялось на 10.0.404);
- Docker с Docker Compose (PostgreSQL 17 запускается в контейнере);
- свободный порт `55432` для базы и `5080` для API;
- `curl` для проверки.

## Запуск

Все команды выполняются из папки `EK1`.

1. Создать файл с паролями и заполнить значения в угловых скобках:

   ```bash
   cp .env.example .env
   ```

2. Поднять базу и дождаться её готовности:

   ```bash
   docker compose up -d --wait db
   ```

3. Запустить API (окружение Development, при первом запуске создаются таблицы и
   тестовые данные):

   ```bash
   set -a && source .env && set +a
   dotnet run --project src/DressTrack.Api
   ```

## Проверка работоспособности

```bash
curl http://localhost:5080/health
```

**Ожидаемый результат:** ответ `200` с текстом `Healthy`.

Проверка входа и границ доступа (пароль — значение `Seed__Password` из `.env`):

```bash
TOKEN=$(curl -s http://localhost:5080/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"login\":\"buyer1\",\"password\":\"$Seed__Password\"}" \
  | sed -E 's/.*"token":"([^"]+)".*/\1/')
curl -s http://localhost:5080/parcels -H "Authorization: Bearer $TOKEN"
```

**Ожидаемый результат:** одна посылка `DT-000001` — посылки других покупателей не видны.
Без заголовка `Authorization` тот же запрос возвращает `401`.

## Тестовые данные

| Логин | Роль | Привязка | Видит посылки |
| --- | --- | --- | --- |
| `seller1` | Продавец | Магазин 1 | DT-000001, DT-000003 |
| `seller2` | Продавец | Магазин 2 | DT-000002 |
| `buyer1` | Покупатель | — | DT-000001 |
| `buyer2` | Покупатель | — | DT-000002, DT-000003 |
| `operator1` | Оператор | Пункт 1 | DT-000001 |
| `operator2` | Оператор | Пункт 2 | DT-000002, DT-000003 |

## Автоматические тесты

```bash
dotnet test
```

Тесты сами поднимают отдельный PostgreSQL через Testcontainers, поэтому нужен только
запущенный Docker. Проверяется: `/health` без входа, `401` без токена, одинаковый ответ
на неверный логин и пароль, `400` на лишнее поле в JSON, списки посылок по привязке
каждого пользователя, одинаковый `404` для чужой и несуществующей посылки, отсутствие
стоимости в ответе оператору.

## Остановка

```bash
docker compose down
```

Данные базы сохраняются в томе `dresstrack-db`; удалить их: `docker compose down -v`.
